그래프는 자기 일을 하고, 원하면 자기를 설명한다. cordboard는 호출자가 고른 그래프에 회선을 꽂고, 무슨 일이 있었는지를 기록의 원본으로 직접 들고 있는다. 통화 내용은 모른다 — 그래프를 묘사하지도, 연결을 막지도 않는다.

cordboard가 직접 만든다 가져와서 쓴다 그래프가 소유한다

전제: 여러 팀이 쓰는 사내 플랫폼이 아니라 혼자 쓰는 로컬 도구다. "노트북에서 계정 없이, 키 없이 뜬다"가 부가 조건이 아니라 주 조건이다. 이 문서는 요약이고, 결정의 정본은 ADR 인덱스다.

정정 · 초기 설계의 첫 문장

레포, 프로세스, 그래프는 서로 다른 것이다

초기 설계는 "레포 하나가 프로세스 하나"에서 출발했다. 패키징 관례를 정체성으로 착각한 것이다(ADR-0002). 이 저장소 하나가 이미 배포 파일 둘로 프로세스 둘을 띄우고, Deployment 하나는 Graph를 여럿 호스팅할 수 있다. cordboard가 연결하는 단위는 레포도 프로세스도 아니고, 호출자가 고른 Deployment의 Graph다.

경계 · ADR-0013 · 0014 · 0015

누가 무엇을 소유하나

교환원은 요청한 상대를 연결하고 통화 기록을 남긴다. 통화 내용을 이해하지 않고, 상대가 어떤 도구로 일하는지 정하지 않으며, 상대의 사정을 보고 회선을 거절하지도 않는다.

cordboard가 직접 만든다
  • 연결 — 고른 Graph의 실행 API 호출
  • 공용 실행 어휘 — Run · Step · Attempt span
  • 기록의 원본 — raw OTLP 아카이브와 질의
  • 카탈로그와 뷰어 계획
  • 선언적 Signal 라우팅 계획
  • 승인함과 만료 시계 계획
  • Deployment 기동 계획
가져와서 쓴다

  • OTel Collector — 도장 검문, 내보내기
  • redact-secret — 비밀 탐지와 공개 정책
  • agent-topology — 토폴로지 포맷과 파생
  • Langfuse — 기록을 읽는 화면
  • uv — 의존성 해석

  • 모델 선택, 공급자 키, SDK, 게이트웨이

  • 인터럽트 위치, 부작용의 멱등성
  • 자기 설명 — 이름, 매니페스트 선택
그 값이 그래프를 묘사하는가, 연결을 묘사하는가?

설정을 하나 더하려 할 때마다 묻는 질문이다. 그래프를 묘사하면 cordboard에 두지 않는다 — 그래프 하나를 붙이려고 cordboard 쪽에 무언가를 써야 한다면 이미 틀렸다. 그래서 그래프마다 붙는 설정 파일도, 매니페스트 안의 cordboard 확장도 없다(ADR-0014). cordboard에 설정이 필요해지면 그것은 연결에 관한 것이다 — 어떤 Deployment가 꽂혀 있나, 무엇이 무엇을 시작하나, Subject를 어떻게 뽑나, 동시성과 승인 만료.

실패 모드 A

두 번째 모놀리스

플랫폼이 그래프 내부를 너무 많이 안다. 새 그래프를 붙이려면 플랫폼을 고쳐야 한다.

증상 — cordboard 쪽에 특정 그래프의 노드 이름, 상태 필드, 모델 설정이 등장하는 순간.

실패 모드 B

아무것도 아닌 층

너무 얇아서 Aegra와 Langfuse를 그냥 쓰는 것보다 나은 게 없다.

증상 — 걷어내도 아무도 불편하지 않은 순간. 자체 트레이서를 가진 그래프(workbench)가 가장 날카로운 시험이다.

실측

통합 경로

Aegra → 그래프 → (선택적) LiteLLM 예제 → Collector로 이어진 실제 아카이브에서 span 40개, 명시적 승격 2회, 상태 격리와 동시 실행의 부모 관계를 확인했다. 실제 모델 공급자 호환성은 실행하지 않았고 주장하지 않는다.

실행 기록의 모양 · ADR-0002 · 0003 · 0008

Run 하나는 trace 하나, Attempt는 Step의 자식

아카이브는 append-only라 트리 모양이 한 번 굳으면 되돌리는 비용이 마이그레이션이 된다. 그래서 데이터가 몇 줄일 때 정했다.

Run  trace 하나 · cord.graph.id · cord.subject.id · cord.semconv.version=0.3.0
└── Step  Node 한 번의 실행 · Outcome: passed | repaired | failed | awaiting_approval | halted
    ├── Attempt 1  tier=fast (선택) · Outcome: failed
    ├── Attempt 2  tier=fast · Outcome: escalated   ← 그래프가 선언한 승격
    └── Attempt 3  tier=deep · Outcome: passed
        └── 그래프 내부의 선택적 span (예: 모델 호출)

승격은 추론하지 않고 선언한다

모델 문자열이나 Tier 순서로 승격을 판정하지 않는다. 같은 Tier 재시도는 승격이 아니다. 결정적 수리로 통과하면 Step은 repaired, 원래 Attempt는 위반 규칙과 함께 failed로 남는다 — 모델이 틀렸다는 사실을 지우지 않는다.

인터럽트는 Step span을 닫는다 선언 · #28

interrupt()에서 Step을 awaiting_approval로 닫고, 재개는 cord.resumed_from을 단 새 Step을 연다. 사람의 판단 시간은 Node가 아니라 Run에 속한다. 규칙의 근거는 workbench가 한 달치 실제 데이터에서 본 14시간짜리 노드 duration이다. 슬라이스 2가 처음 실데이터로 시험한다.

Subject가 묶고, Thread는 묶지 않는다

Thread는 체크포인터의 키라서 같은 Thread의 다음 실행은 앞의 상태를 물려받는다. 독립 실행은 새 Thread로 하고, 여러 실행은 필수 불투명 문자열인 Subject로 묶는다. Langfuse에서는 session_id가 된다.

재개는 아직 논리 Run이 아니다

Aegra 0.10.4는 재개에도 새 API Run ID를 낸다. 여러 API 호출을 하나의 논리 Run으로 잇는 규약은 승인·재개 통합(슬라이스 2)의 몫으로 미뤄 두었다.

기록 경로의 관문 · ADR-0005 · 0006

지운 것만 들어온다

한 번 샌 비밀은 회수할 수 없다. 그래서 지우는 곳과 검문하는 곳을 나눴다. 지우기는 span을 만든 프로세스 안에서, 검문은 Collector에서.

그래프 프로세스

지우고 도장

공개 OTel 인코더로 envelope 전체를 만들고 문자열마다 redact-secret의 기본 정책을 적용한다. 성공해야만 도장을 찍는다. block 판정이 하나라도 있으면 치환 결과가 있어도 span을 통째로 버린다.

Collector

도장만 본다

또 하나의 탐지기가 아니라 관문이다. 도장 없는 span은 버린다. 리댁터를 빼면 조용히 새는 게 아니라 아카이브가 비어서 즉시 보인다. Langfuse 콜백을 직접 다는 것은 이 관문을 우회하므로 금지다.

아카이브

원본은 우리가 든다

날짜별 raw OTLP JSONL이 기록의 원본이다. "raw"는 포맷이지 지우지 않았다는 뜻이 아니다. 전체 프롬프트·diff·모델 출력은 span 속성에 넣지 않는다. Langfuse는 같은 기록을 읽는 두 번째 목적지다.

자기 설명 · ADR-0009 · 0011 · 0012 · 0015

매니페스트는 관문이 아니라 그림의 재료다

Deployment는 두 문서를 낼 수 있다 — 바깥에 보이는 A2A agent-card.json(우리 필드 0개)과 안의 구조를 담은 agent-topology.manifest.json. 그래프가 자기 프로세스에서 agent-topology로 파생하고, cordboard는 받은 그대로 읽는다. 둘 다 연결의 전제조건이 아니다.

매니페스트 상태연결 · 기록카탈로그 · 뷰어
없음정상그림 없이 실행 기록만 보여준다
있고 스키마에 맞음정상그림을 그리고 실행 기록을 대조한다
스키마 위반정상경고 그 문서를 쓰지 않는다
표류 — 게시본 ≠ 현재 구조정상, 기동도 멈추지 않음경고 그림을 낡은 상태로 표시하고 대조하지 않는다. 갱신 경로 안내

거짓말은 연결이 아니라 화면에서 막는다

예전에는 표류하면 기동을 거부했다 — "경고는 며칠 뒤 눈이 걸러내고, 그때부터 뷰어가 거짓말한다." 관찰은 옳다. 다만 해로운 것은 표류가 아니라 낡은 그림을 현재처럼 보여주는 것이다. 표류한 그림은 보이는 모양 자체가 바뀌므로 로그 한 줄처럼 걸러지지 않는다.

병렬 분기 안의 인터럽트는 경고

한 source에서 나가는 direct 엣지가 둘 이상이고 그 대상에 정적 인터럽트가 있으면 경고한다. 재개 불가 위험(langgraph#6626)은 그래프 자신의 실행 안에서 생긴다. 병렬 여부는 agent-topology의 실험적 branch 해석에서 오고, unknown이면 "확인할 수 없음"으로 표시한다. 동적 interrupt()는 토폴로지에 보이지 않으므로 다루지 않는다.

격리 · ADR-0001

프로세스 분리는 원칙이 아니라 기본값

처음엔 "경계를 OS가 강제한다"는 원칙으로 세웠다가 논거가 틀려서 강등했다. 경계가 하나가 아니라 둘이었다.

경계 1 — 이 프로젝트의 테제

cordboard는 그래프 소스를 모른다

계약이 지킨다 — 실행 API와 span, 그리고 그래프가 원하면 내는 매니페스트. 프로세스 개수와 무관하다. 한 프로세스에 그래프가 열 개 있어도 cordboard는 그 계약만 읽는다.

경계 2 — 곁가지

그래프 A가 그래프 B를 import하지 못한다

프로세스가 지킨다. 다만 테제가 아니다. 기본이 격리면 실수는 "메모리를 좀 더 썼다"이고 바로 보인다. 기본이 공유면 실수는 "몰랐는데 얽혀 있었다"이고 늦게 발견된다. 앞쪽이 싸다.

어느 그래프가 프로세스를 공유하는지는 cordboard 설정이 아니라 Aegra 배포 파일이 표현한다. Signal이 올 때 기동하고 유휴 시 내리는 지연 기동은 라우팅과 함께 슬라이스 3에서 다룬다. 프로세스가 떠 있지 않을 때 카탈로그가 보여줄 수 있는 것은 마지막으로 받은 매니페스트다.

앞으로의 연결 · 계획

무엇이 무엇을 시작하나

여기부터는 아직 구현이 없다. 모두 연결에 관한 것이라 cordboard의 몫이다.

Signal 출처예슬라이스
manual개발 중 대부분의 실행3
file노트 파일이 바뀌면 — 로컬 도구라 오히려 자주 쓴다3
schedule매일 정해진 시각3
http아무 웹훅. GitHub은 한 사례일 뿐 — 로컬 터널링 마찰로 뒤로이후
run.finished다른 Run의 종료. 그래프끼리 비동기로 엮이는 지점4

Rule이 Signal을 Assistant와 입력으로 바꾸고 Subject를 뽑는다. 라우터는 Signal ID로 중복을 없애고 (Assistant, Subject)에 동시성 정책을 적용하며, 어느 Rule에도 맞지 않은 Signal도 기록한다. 체인된 Run은 새 trace를 만들고 cord.caused_by.run_id로 앞 Run을 가리키며 cord.cascade.depth로 깊이를 남긴다. 동기 합성은 그래프 안의 서브그래프로 한다.

승인은 항상 interrupt_id를 동반한다. 어디서 멈추고 답을 어떻게 해석할지는 그래프가, 승인함과 리마인드·만료 시계는 cordboard가 갖는다.

불행 경로와 결정

원래 주인이 없던 자리들

흐름을 끝까지 그려서 드러난 자리다. 테두리가 황토인 둘은 2026-09-12 경계 정정으로 처분이 바뀐 것이다.

01

같은 Signal이 두 번

웹훅 중복 발송은 정상 동작이다.

Signal ID로 중복 제거 + (Assistant, Subject) 동시성 정책. #17

02

부작용이 두 번 실행

재개하면 인터럽트된 노드가 처음부터 다시 돈다.

부작용의 멱등성은 그래프 소유. 인터럽트 노드와 부작용을 분리하는 템플릿, 뷰어의 중복 Step 표시. #15

03

재개 값은 하나인데 인터럽트가 여럿

대기 중 인터럽트가 여럿이면 ID 없이 재개할 수 없다.

승인은 하나뿐일 때도 예외 없이 interrupt_id를 동반한다. #14

04

아무도 승인하지 않는다

Run이 영원히 멈춰 있다.

만료 시계는 cordboard가 집행한다. 만료 기간은 그래프 설명이 아니라 연결 단위 설정이다. #15

05

프로세스가 죽는다

실행 중인 Run의 워커가 사라진다.

런타임 복구는 Aegra 소관. 카탈로그는 unreachable로 표시한다.

06

Run이 Run을 무한히 부른다

run.finished가 Signal이 되면 순환이 생긴다.

cord.cascade.depth로 깊이를 기록하고 상한을 둔다. #18

07

트레이스가 경계에서 끊긴다

호출자, 그래프, 선택적 게이트웨이가 서로 다른 프로세스다.

W3C Trace Context로 잇는다 — 실측 완료. 체인된 Run은 새 trace, cord.caused_by.run_id로 연결. #7 · #9

08

Signal이 어느 Rule에도 안 맞는다

조용히 사라지고 있었다.

매칭 실패도 기록한다. #16

09

병렬 분기 안에 인터럽트

걸리면 그 Run은 재개할 수 없다.

예전: 등록 거부. 지금: 경고로 계속 보이게 한다. 위험은 그래프의 실행 안에서 생기고, 실행은 호출자의 선택이다. ADR-0015

10

매니페스트가 표류했다

뷰어가 현재와 다른 그림을 그린다.

예전: 기동 거부. 지금: 그림을 낡은 상태로 표시하고 실행 기록을 대조하지 않는다. ADR-0015 · #13

어휘 · ADR-0002

데이터에 굳는 이름은 정밀하게

속성 키와 닫힌 목록 값은 몇 주치 데이터에 굳으므로 정밀함이 값을 한다. 사람이 말할 때 쓰는 단어는 문맥이 해결한다 — 금지어가 아니라 매핑이다. 같은 단어가 OTel · Langfuse · LangGraph 등에서 어떻게 다른지는 용어집에 있다.
