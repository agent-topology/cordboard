cordboard는 열한 개의 기존 이름 체계 위에 앉는다. 그들이 같은 단어를 다르게 쓴다. 이 용어집은 금지 목록이 아니라 지도다 — 각 단어가 출처마다 무슨 뜻이고, cordboard 문서에서는 무슨 뜻으로 쓰는지를 적는다. "이 Run trace해봐"는 그대로 통한다. 애매할 때 여기서 매핑을 본다.

ADR-0002 §3 · §5 · §6

정밀함은 두 곳에만 강제한다

아카이브는 append-only라, 데이터에 굳는 이름을 잘못 쓰면 되돌리기가 비싸다. 사람이 말할 때 쓰는 단어는 문맥이 해결한다. 그래서 규칙은 데이터에 굳는 이름에만 걸고, 대화에는 정의만 둔다.

(a) cord.* 속성 키

지금 코드가 실제로 기록하는 키

cord.run.idcord.graph.idcord.subject.id cord.subject.typecord.node.namecord.step.attempt cord.tiercord.outcomecord.redacted cord.semconv.versioncord.archive.date

이름은 정했지만 아직 기록하지 않는 키

cord.signal.idcord.cascade.depth cord.caused_by.run_idcord.resumed_from

cord.archive.date는 Collector가 아카이브 날짜 분할용으로 resource에 붙인다.

(b) 닫힌 목록의 값

질의가 이 문자열에 직접 걸린다. 값 추가는 코드 변경이 아니라 어휘 변경이고 ADR이 필요하다.

  • Step Outcome — passed · repaired · failed · awaiting_approval · halted
  • Attempt Outcome — passed · failed · escalated

손대지 않는 이름

  • 와이어 필드 — trace_id · traceparent · span_id · session_id · thread_id. 프로토콜이지 우리 명사가 아니다
  • gen_ai.* — 이미 이름이 있으면 빌린다. 전부 Development 상태라 이름을 빌려도 안정성은 가정하지 않는다
ADR-0002 §4

수식 <source>.<word>은 필요할 때만

  1. 아래 사전에서 충돌이나 주의인 단어는 문맥이 애매할 때 붙인다
  2. cord.는 기본 네임스페이스라 cordboard 문서 안에서는 생략한다. 같은 문단에 남의 것이 나오면 붙인다
  3. 충돌 없는 단어에는 붙이지 않는다. otel.Collector는 과잉이다
  4. 코드에서는 속성 접두사가 이미 그 일을 한다. cord.tier에 또 붙이지 않는다

접두사는 신호다. 전부 붙이면 아무 의미도 없어진다.

이전 판이 틀렸던 곳

우리가 먼저 틀렸다

용어집이 살아 있지 않으면 틀린 정의가 쌓인다. 테두리가 황토인 셋은 2026-09-12에 드러났다.

01

금지어 목록 자체

첫 판은 event · agent · trace · session · thread 등을 금지했다. 데이터 이름의 해법을 대화에 넓힌 것이다. "이 Run trace해봐" 같은 자연스러운 문장에 대체어 표가 필요해졌다.

→ 금지를 폐기하고 정의와 매핑으로 대체 (ADR-0002 §2)

02

우리가 금지한 단어를 속성 키에 썼다

chain을 금지해 놓고 cord.chain.depth에 넣었다. LangChain과 Langfuse 양쪽과 부딪힌다. 데이터에 굳는 이름이라 여기서는 정밀함이 값을 한다.

→ cord.cascade.depth로 개명

03

Signal도 안전하지 않았다

OTel이 traces · metrics · logs를 "signals"라 부른다. "아무와도 충돌하지 않는다"는 판단이 틀렸다.

→ 이름은 유지하고 충돌 목록에 올린다. 텔레메트리 얘기 중엔 수식

04

Graph · Manifest · Deployment를 잘못 정의했다

Graph는 "레포 하나", Manifest는 "cord.yaml", Deployment는 "Graph와 1:1"이라고 적었다. 레포 하나가 배포 파일 둘로 프로세스 둘을 띄우고, 매니페스트는 그래프의 선택적 자기 설명이다.

→ ADR-0014 · ADR-0015에 맞춰 다시 정의

05

graph id가 셋이었다

실행 기록의 cord.graph.id, Aegra 배포 파일의 graph 키, 토폴로지 문서의 graphs[].id. 마지막 것은 문서 안의 주소일 뿐인데 정체성처럼 다뤘다.

→ 아래 "graph id" 항목. 셋은 같은 것이 아니다

06

매핑을 확인하지 않고 적었다

이전 판은 "Attempt는 Langfuse의 Generation", "Verdict는 Score로 저장", "Subject는 baggage로 전파"라고 적었다. 코드와 대조하니 셋 다 사실이 아니었다.

→ 모든 항목을 코드와 실측 문서에 대조해 다시 썼다

사전

단어별 뜻과 cordboard에서의 쓰임

충돌 같은 문맥에서 다르게 쓰여 위험한 단어 · 주의 문맥이 달라 덜 부딪히는 단어 · 참고 충돌은 없지만 정의가 필요한 단어. 여기 없는 단어는 안전하다는 뜻이다.
