# ADR-0011: Manifest의 그래프 모양은 파생하고, 표류하면 기동을 거부한다

**Status:** Accepted — 표류 시 기동 거부는 [ADR-0015](0015-never-block-connection.md)가 경고로 대체
**Date:** 2026-09-10
**Deciders:** 단독 (로컬 도구, 저자 = 운영자)
**관련:** ADR-0002 (어휘 — Graph의 정체성), ADR-0009 (well-known 두 문서), ADR-0007 (등록 거부)
**슬라이스:** 1 — 카탈로그와 뷰어가 생기는 시점

> **정정 기록.** 첫 판은 파생 로직을 **cordboard가 만든다**고 전제했다. ADR-0012에서 그 로직을
> `agent-topology` 독립 라이브러리로 분리했으므로, cordboard는 그것을 **호출**한다.
> 그리고 실제로 생산자를 구현하면서 파생 가능 범위가 확정됐다 — 아래 "확인된 것"에 적는다.

---

## Context

ADR-0002에서 Graph를 재정의했다 — 레포도 프로세스도 아니고 **Manifest로 자기를 설명하는 실행 단위**다. 그러면 Manifest가 곧 정체성이고, Manifest가 틀리면 정체성이 틀린 것이다.

### 손으로 쓴 노드 목록은 반드시 어긋난다

초기 설계에서는 `cord.yaml`에 사람이 노드 목록을 적게 했다.

```yaml
nodes: [read_issue, verify, draft_commit, await_approval, publish]
```

이건 실패한다. 코드에 노드를 추가하고 yaml을 안 고치면 끝이다. 그리고 그 실패가 **조용하다** — 시스템은 정상 동작하고 화면도 뜬다.

**어긋난 Manifest는 없는 것보다 나쁘다.** 뷰어가 존재하지 않는 그래프를 그린다. 성공 기준 B("뷰어 소스에 Node 이름이 없다")를 만족해도 화면이 거짓말한다. 그리고 그 거짓말을 근거로 디버깅하게 된다.

### 다행히 파생이 가능하다

LangGraph의 컴파일된 그래프에서 구조를 프로그램으로 꺼낼 수 있다. `graph.get_graph()`가 `nodes: dict[str, Node]`와 `edges: list[Edge]`를 가진 객체를 반환하고, 거기에 `draw_mermaid()` · `draw_ascii()` · `draw_mermaid_png()`가 붙어 있다.

### 확인된 것 — 생산자를 실제로 만들어 측정했다

추측이 아니라 LangGraph를 설치해 컴파일된 그래프를 읽어 확인했다.

| 항목 | 파생되나 |
|---|---|
| 노드 id, 엣지, 조건부 여부 | ✓ |
| 조건부 엣지의 **라벨** | ✓ `edge.data`에 문자열로 (path map을 준 경우) |
| **정적** 인터럽트 | ✓ `node.metadata['__interrupt']` = `before`/`after` |
| **동적** 인터럽트 (노드 본문의 `interrupt()`) | ✗ **전혀 안 보임** |
| 서브그래프 여부 | ✓ xray 확장 시 접두사가 붙는지로 판별 |
| 서브그래프 내부 | △ 불안정 |
| path map 없는 조건부 엣지의 목적지 | ✗ **그리고 가짜 엣지가 생긴다** |

마지막 항목이 예상보다 나쁘다. 목적지가 빠지는 정도가 아니라 라우팅 노드에서
`__end__`로 가는 **존재하지 않는 무조건 엣지**가 나타난다. 대상 노드들은 고아가 된다.
그래서 `ORPHANED_NODES` 갭이 이 경우의 탐지 신호가 된다.

동적 인터럽트가 안 보이는 것은 ADR-0007의 R3에 직접 영향을 준다 — 그쪽에 반영했다.

### 그런데 파생이 완전하지는 않다

**조건부 엣지가 안 보일 수 있다.** LangGraph 문서가 명시한다 — `Command[Literal["node_b", "node_c"]]` 같은 반환 타입 애노테이션이 **그래프 렌더링에 필요하고**, 그것이 `node_a`가 어디로 갈 수 있는지를 LangGraph에 알려준다. 애노테이션 없이 `Command`로 라우팅하면 그 목적지는 파생 결과에 안 나타난다.

**서브그래프 xray에 미해결 버그가 있다.** 서브그래프 진입점을 향하는 엣지가 있으면 `xray=True` 렌더링이 실패하고(#593), 3단계 이상 중첩하면 `Graph.extend()`가 콜론으로 이어붙인 계층 ID를 만들어 노드 이름이 읽을 수 없는 이스케이프 형태로 나온다(#35492).

### 그리고 경계를 깨면 안 된다

파생하려면 그래프 코드를 import해야 한다. 플랫폼이 그걸 하면 실패 모드 A다.

## Decision

### 1. Manifest를 두 절로 가른다

| 절 | 누가 쓰나 | 무엇 |
|---|---|---|
| **declared** | 사람이 `cord.yaml`에 | 코드에서 뽑을 수 없는 것 — Subject 추출식, 승인 정책, 동시성, 트리거 |
| **derived** | `cordboard`가 컴파일된 그래프에서 | 코드가 곧 진실인 것 — nodes, edges, 인터럽트 노드, mermaid |

**derived는 사람이 손대지 않는다.** 편집하면 다음 기동에서 덮어써진다.

### 2. 파생은 그래프 자기 프로세스가, `agent-topology`를 써서 한다

```python
from agent_topology.langgraph import describe
document = describe(compiled_graph)          # 시그니처: (compiled, *, depth=0, strict=False)
```

**`describe()`에 이름 인자가 없다.** 그래프가 `id: "main"`, `name: "LangGraph"`로 나오므로
**cordboard가 `cord.yaml`의 이름으로 덮어써야 한다.** 그러지 않으면 모든 그래프가 같은 이름이 된다.

> **2026-09-12 정정.** 이 결정을 철회한다 ([ADR-0014](0014-no-graph-descriptors.md)). cordboard는
> 생성 문서를 덮어쓰지 않는다. 전제도 틀렸다 — 표시 이름은 원래 `compile(name=...)`로 정할 수
> 있었고, 문서 안 graph id는 `agent-topology` 0.1.0b3부터 `describe(graph_id=...)`로 정한다.

또는 CLI로:

```
agt describe src/my_agent/graph.py:graph --out topology.json
```

`agt`는 대상 파일을 import해 컴파일된 객체를 얻을 뿐 **그래프를 실행하지 않는다.**
종료 코드가 구분돼 있어서 `cord up`이 원인별로 다르게 대응할 수 있다 —
`2` 문법 오류 · `3` import 실패 · `4` 객체 해석 실패 · `5` 지원하지 않는 LangGraph 버전 ·
`6` strict 모드에서 갭 발견 · `7` 쓰기 실패 · `8` 그 외.

**cordboard는 파생 로직을 소유하지 않는다.** 라이브러리를 부를 뿐이고, 그 라이브러리는 cordboard를 모른다.
그래서 파생 품질이 cordboard가 아니라 적합성 픽스처로 검증된다.

**플랫폼은 결과 JSON만 읽는다.** 경계는 안 깨진다. 파생하는 주체가 그래프 자신이므로 오히려 경계가 강화된다.

### 3. 표류하면 기동을 거부한다

`cord up`이 매번 다시 뽑아 게시된 것과 비교하고, 다르면 **기동을 멈춘다.**

```
$ cord up
✗ issue-resolver — manifest drift
  derived nodes  : read_issue, draft_commit, review, await_approval, publish
  published      : read_issue, draft_commit, await_approval, publish
  → 'review' 가 코드에 있는데 게시본에 없습니다. cord sync 로 갱신하세요.
```

권고가 아니라 구조로 막는다. **경고로 두면 무시되고, 무시되면 뷰어가 거짓말한다.**

> **2026-09-12 정정.** 기동을 멈추지 않는다 ([ADR-0015](0015-never-block-connection.md)). 거짓말은
> 연결이 아니라 화면에서 막는다 — 표류한 그림은 낡은 상태로 표시하고 실행 기록을 대조하지 않는다.
> 보이는 것이 바뀌므로 경고처럼 걸러지지 않는다.

`derived_from`에 entrypoint 소스의 해시를 함께 기록해서 비교를 싸게 만든다.

### 4. 표류 검사는 구조 해시로, cordboard가 직접 비교한다

문서 최상위에 `structureHash: {algorithm, algorithmVersion, value}`가 있고,
`agent_topology.spec.compute_structure_hash`로 다시 계산할 수도 있다.
0.1에는 `agt diff`가 없으므로 **비교는 cordboard가 한다 — 값 하나를 대조하는 것으로 끝난다.**
해시가 구조만 덮기 때문에 타임스탬프나 주석 변경으로 오탐이 나지 않는다.

### 4b. JSON이 정본, Mermaid는 같이 싣는 부산물

Mermaid는 **렌더링 언어이지 데이터 모델이 아니다.** 파싱해 되돌리면 조건부 엣지 라벨·인터럽트 표시·노드 메타데이터가 문자열로 뭉개진다.

JSON을 계약으로 하고 mermaid 문자열을 같이 넣는다. README에 붙이거나 뷰어가 대체 렌더링으로 쓸 때 편하고, 비용은 필드 하나다.

### 5. 한계는 문서 안에 실려 다닌다 — 그리고 **두 종류다**

내 프로토타입은 모든 한계를 `gaps`에 넣었고, 그러면 `DYNAMIC_INTERRUPTS_UNKNOWN`처럼
항상 존재하는 항목 때문에 **모든 문서가 영구히 incomplete**가 된다. 실제 스펙은 둘을 나눈다.

| | 무엇 | 문서를 incomplete로 만드나 |
|---|---|---|
| `completeness.gaps` | **이 그래프**에서 못 뽑은 것 | ✓ |
| `producerLimitations` | **이 생산자**가 원래 못 보는 것 | ✗ |

`strict=True`는 전자에서만 `IncompleteTopologyError`를 던지고, 그 예외의 `.document`에
불완전한 문서가 그대로 담겨 있어 호출자가 같은 결과를 보고할 수 있다.

**cordboard는 둘 다 표시하되 등록 판정에는 쓰지 않는다.** 갭이 있어도 등록은 된다(ADR-0007).

### 5b. 파생 한계는 경고로 드러낸다 — 숨기지 않는다

```
⚠ issue-resolver — 조건부 엣지 2개의 목적지가 선언되지 않았습니다.
  Command 반환에 Literal 애노테이션을 붙이면 그래프에 나타납니다.
  router_node, dispatch_node
```

그리고 `cord new` 템플릿이 애노테이션을 기본으로 넣는다. 규율이 아니라 스캐폴드로 해결한다.

### 6. 서브그래프는 기본적으로 불투명 노드 하나

`describe(compiled, depth=0)`이 기본이다 — 불리언 xray가 아니라 **깊이 정수**다.
필요하면 `cord.yaml`에서 옵트인한다.

```yaml
derive:
  depth: 1     # 한 단계만 펼침
```

옵트인해도 확장된 형태가 자식의 join·라우팅·인터럽트 선언을 완전히 보존하지 못하며,
그 사실이 `expanded-subgraph-metadata` 갭으로 문서에 남는다.

### 7. derived 절이 없으면 등록되지 않는다

앞선 설계에서는 "등록은 막지 않되 경고를 남긴다"는 관대한 정책이었다. **정정한다.**

| | 정책 |
|---|---|
| derived 절 없음 | **등록 거부** — 생성되는 것이라 비용이 0이고, 이게 정체성이다 |
| 표류 (derived ≠ 게시본) | **기동 거부** |
| declared 절이 부분적 | 등록. 선언한 만큼만 기능을 얻는다 |
| 파생 한계 (조건부 엣지 등) | 등록. 경고 |

declared는 부분적이어도 되고 derived는 필수다. **비대칭이 의도적이다** — 하나는 사람의 판단이고 하나는 기계가 뽑는 사실이다.

## Options Considered

### Option A: 사람이 전부 쓴다 (초기 설계)

**Pros:** 구현이 없다. 그래프 코드를 import할 필요가 없다.
**Cons:** 반드시 어긋난다. 그리고 조용히 어긋난다. 뷰어가 거짓말을 시작한다.

### Option B: 전부 파생한다

노드도 엣지도 트리거도 Tier도 전부 코드에서 뽑는다.

**Pros:** 표류가 원천 불가능하다. 설정 파일이 사라진다.
**Cons:** Subject 추출식·승인 만료·동시성 정책은 **코드에 없는 정보**다. 억지로 넣으려면 데코레이터나 매직 주석이 필요하고, 그건 `cordboard`가 그래프 코드에 침투하는 것이다 — 실패 모드 A의 다른 얼굴.

### Option C: 사람이 쓰고 CI가 검사한다

`cord.yaml`은 손으로 쓰되 CI가 코드와 비교해 경고.

**Pros:** 기존 설계를 안 바꾼다.
**Cons:** 로컬 도구에 CI가 전제된다. 그리고 경고는 무시된다. **어긋난 상태로 계속 돌아간다** — 문제의 본질이 그대로다.

### Option D: 두 절로 나누고, derived는 파생 + 표류 시 기동 거부 ← **채택**

**Pros:** 코드가 진실인 것은 코드에서, 사람의 판단인 것은 사람이. 표류가 구조적으로 불가능. 파생 주체가 그래프 자신이라 경계가 강화된다.
**Cons:** 파생 로직과 비교 로직이 필요하다. 파생 한계가 그대로 노출된다. 기동 거부가 개발 중에 성가시다.

## Trade-off Analysis

### 왜 경고가 아니라 거부인가

`cord up`이 표류를 경고만 하면, 개발 중에 그 경고를 매일 보게 되고 며칠 뒤 눈이 그걸 걸러낸다. 그리고 어느 시점부터 뷰어가 조용히 거짓말한다.

**거부가 개발 중에 성가신 것이 이 결정의 목적이다.** ADR-0006의 Collector 관문과 같은 발상 — 조용한 실패를 시끄러운 실패로 바꾼다. 성가심은 비용이 아니라 기능이다.

완화는 `cord sync` 하나다. 한 명령으로 다시 뽑아 게시본을 갱신한다.

### derived와 declared의 비대칭

declared가 비어 있어도 등록되는데 derived는 필수인 것이 이상해 보일 수 있다. 기준은 **비용과 성질**이다.

| | derived | declared |
|---|---|---|
| 만드는 비용 | 0 (생성됨) | 사람의 판단 |
| 없으면 | 정체성이 없다 | 기능이 적을 뿐이다 |
| 틀리면 | 화면이 거짓말한다 | 트리거가 안 걸린다 — 눈에 보인다 |

declared가 틀리면 증상이 즉시 나타난다. derived가 틀리면 조용하다. 그래서 강도가 다르다.

### 파생 한계를 숨기지 않는 이유

조건부 엣지가 일부 안 보이는 그래프도 등록은 된다. 완벽하지 않은 파생이 손으로 쓴 것보다는 낫기 때문이다.

다만 **뷰어가 "이 그래프의 모양은 불완전할 수 있음"을 표시해야 한다.** 안 하면 사용자가 화면을 완전한 것으로 믿는다. 부분적으로만 정확한 화면은 부정확한 화면보다 위험하다 — 어디까지 믿을지 모르기 때문이다.

### 파생이 경계를 강화한다

직관과 반대로 보인다 — 코드를 import하는 게 경계를 약하게 만드는 것 아닌가?

아니다. **import하는 주체가 그래프 자신**이다. 그래프가 자기 코드를 자기 프로세스에서 읽어 JSON을 낸다. 플랫폼은 그 JSON만 본다.

오히려 손으로 쓰는 쪽이 위험하다. 사람이 옮겨 적는 과정에서 그래프 내부 지식이 플랫폼 설정 파일로 새어 나오고, 그게 실패 모드 A가 시작되는 모양이다.

---

## Consequences

### 쉬워지는 것

- Manifest가 코드와 어긋날 수 없다
- 노드를 추가할 때 yaml을 고칠 필요가 없다 — 마찰이 준다
- 뷰어가 그리는 것이 실제 그래프임이 보장된다
- mermaid가 공짜로 따라와서 README·PR 설명에 쓸 수 있다
- 남이 만든 Deployment도 같은 규칙으로 검증된다

### 어려워지는 것

- **기동 거부가 개발 중에 성가시다.** 의도된 것이지만 `cord sync`가 반드시 있어야 한다
- **파생 로직이 LangGraph 내부 API에 의존한다.** `get_graph()`의 반환 모양이 바뀌면 따라가야 한다
- **파생 한계가 그대로 드러난다.** 조건부 엣지 경고가 자주 뜨면 무시하게 될 위험 → 템플릿이 애노테이션을 기본으로 넣어 발생 자체를 줄인다
- **서브그래프 그래프는 덜 보인다.** 불투명 노드 하나로 뭉개진다. xray 버그가 고쳐지면 재검토
- **`derived_from` 해시 계산 방식을 정해야 한다.** entrypoint 파일만? import 그래프 전체? 전자는 놓치고 후자는 비싸다

### 다시 볼 조건

- **LangGraph의 `get_graph()`가 바뀌면** → `agent-topology` 쪽 문제가 된다. cordboard는 안 건드린다
- **두 번째 생산자(LCEL 등)가 생기면** → 포맷이 LangGraph 전용인지 판명된다. 그때 `structure` 스키마를 재검토
- **xray 버그(#593, #35492)가 고쳐지면** → 서브그래프 기본값을 재검토
- **조건부 엣지 경고가 대부분의 그래프에서 뜨면** → 애노테이션 없이도 목적지를 알아낼 방법이 있는지(정적 분석 등) 검토. 없으면 그 한계를 문서화하고 수용
- **LangGraph 아닌 오케스트레이터를 등록하고 싶어지면** → 파생 규약을 프레임워크별로 정의할지, 아니면 `derived` 절을 직접 만들어 내는 것을 허용할지 결정. 후자면 표류 검사가 그 그래프에는 무의미해진다

## 정정 — 선언 절과 이름 덮어쓰기 폐기 (2026-09-12)

[ADR-0014](0014-no-graph-descriptors.md)가 그래프 단위 설정을 폐기했다. 이 ADR에서 바뀌는 곳은 넷이다.

- **결정 1:** Manifest를 declared·derived 두 절로 가르지 않는다. Manifest는 파생된 문서 하나다.
  "derived는 사람이 손대지 않는다"는 그대로이고, 이제 cordboard도 손대지 않는다.
- **결정 2:** 이름 덮어쓰기를 철회한다. 표시 이름은 `compile(name=...)`, 문서 안 graph id는
  `describe(graph_id=...)`로 그래프 프로세스가 정한다. 0.1.0b3의 시그니처는
  `describe(compiled_graph, *, graph_id="main", depth=0, strict=False)`다.
- **결정 4:** 매니페스트 안의 graph id는 `structureHash`에 들어간다. 같은 그래프라도 id를 바꾸면
  해시가 바뀌어 표류로 보인다. 이 id는 업스트림 정의상 문서 안 주소일 뿐이므로 그래프 하나짜리
  문서는 기본값 `main`으로 충분하다.
- **결정 6:** 서브그래프 깊이는 설정 파일의 옵트인이 아니라 그래프 프로세스의 `describe(depth=...)`
  인자다. `depth≥1`에서 부모 노드가 사라지는 문제(AT-1)는 0.1.0b3에서도 열려 있다.

바로 위 #7 정정의 "Subject·승인·동시성·트리거 등 연결 계약의 선언은 유지한다"도 대체한다.
그것들은 매니페스트의 선언 절이 아니라 보드 단위 연결 설정이다.


## 정정 — 표류는 기동을 막지 않는다 (2026-09-12)

[ADR-0015](0015-never-block-connection.md)가 결정 3의 "표류하면 기동을 거부한다"와 그 근거 절
"왜 경고가 아니라 거부인가"를 대체한다. 파생은 그래프 프로세스가 한다는 결정, 표류를 구조 해시로
검사한다는 결정, `cord sync`가 갱신 경로라는 결정은 그대로다. 바뀌는 것은 표류가 감지됐을 때의 행동이다.

"경고로 두면 무시되고, 무시되면 뷰어가 거짓말한다"는 관찰은 옳다. 다만 해로운 것은 표류가 아니라
**낡은 그림을 현재인 것처럼 보여주는 것**이다. 그러니 기동을 막는 대신 화면을 바꾼다. 표류한 그림은
낡은 상태로 표시하고, 실행 기록을 그 그림에 대조하지 않는다. 로그 한 줄이 아니라 보이는 것이
달라지므로 눈이 걸러낼 수 없다. 표류해도 연결과 기록은 온전하다.

위 거부 표의 두 행도 대체된다. "derived 절 없음 — 등록 거부"는 없어지고(매니페스트 부재는 상태),
"표류 — 기동 거부"는 위 행동으로 바뀐다.
