>

## 슬라이스 0에 필요한 것 — 전부 작성됨

슬라이스 0은 위험 1(어휘가 질의에 답하는가)과 위험 2(마스킹 관문이 작동하는가)를 시험한다.
그 과정에서 **되돌리기 어렵게 못 박히는 것은 셋**이고, 넷째는 슬라이스 0이 실제로 사용한다.

| ADR | 슬라이스 0에서 못 박히는 것 | 시험하는 작업 |
|---|---|---|
| **0008** | span 트리 모양 — Attempt가 자식 span이고 `escalated`가 선언된다 | 작업 3 (관문) |
| **0005** | 아카이브 포맷 — raw OTLP JSONL, 이것이 기록의 원본 | 작업 2 · 3 |
| **0006** | 마스킹 지점 — 프로세스 안에서 지우고 Collector가 검문. **0.1.0b1 설치·관문 검증 완료 (#5)** | 작업 2 · 종료 판정 ②③ |
| **0004** | Tier↔Model 분리, 승격은 그래프 소유 | 작업 4 |

셋이 append-only 아카이브에 구조로 남기 때문에, **데이터가 다섯 줄일 때 확정해야 하고 그 뒤로는 마이그레이션이 된다.**
슬라이스 0 작업 3이 "Attempt 계층을 일부러 잘못 만들어 보고 질의가 깨지는 걸 확인한다"까지 포함하는 이유다.

## 작성 과정에서 드러난 것

**0001은 논거가 틀렸다.** "경계를 OS가 강제한다"는 원칙이었는데, 경계가 둘이었고 이 프로젝트의 테제인 경계 1은 계약이 지키지 프로세스가 지키지 않는다. 결론은 유지되지만 원칙에서 기본값으로 강등됐고, 원래 검토에서 빠져 있던 지연 기동이 슬라이스 3으로 들어갔다.

**0008은 분류가 틀렸다.** 처음에 "어휘 결정이라 ADR 불필요"로 뒀는데, 실제로는 아카이브의 물리적 구조를 정하는 결정이었다.

**0002는 두 번 틀렸다.** 처음엔 "ADR 불필요"로 분류했고(0008과 같은 이유로 틀렸다), 그다음엔 **방향이 틀렸다** — 겹치는 단어를 금지어로 처리했는데, 그게 자연스러운 표현을 막고 이해를 개선하지 않는 순수한 마찰이었다. 금지를 걷어내고 매핑으로 대체했다.

핵심은 이 구분이다 — **데이터에 굳는 이름**(속성 키, 닫힌 목록 값)에서는 정밀함이 값을 하고, **사람이 말할 때 쓰는 단어**에서는 문맥이 해결한다. 첫 판은 전자의 해법을 후자에 확장했다.

**0006은 전제가 바뀌었다.** 첫 판은 "패턴 목록을 직접 관리한다"를 전제로 썼는데, 같은 저자의 `redact-secret`이 이미 그 구조를 갖추고 있었고 Rust 코어 마이그레이션으로 언어 장벽까지 사라졌다. 전면 재작성했다.

ADR을 쓰는 값이 결정을 기록하는 데만 있는 게 아니라는 증거가 다섯 건 나왔다. 그중 하나(0002)는 결정 자체가 뒤집혔다.

## 외부 의존 — 릴리스 선행 조건 충족 (2026-09-11)

ADR-0006의 Rust 코어/PyO3 릴리스 선행 조건은 `redact-secret==0.1.0b1` 설치로
충족됐다. 공개 API의 redact/block/unchanged와 실제 Collector 관문을 검증했다.
마스킹 없이 시작한다는 RS-5의 이전 문장을 폐기했으며 임시 탐지기나 정책 우회는 없다.
[실제 명령과 증거](../archive.md)를 기준으로 삼는다. 그래프 #4 연결은 후속이다.

## cordboard는 두 업스트림 프로젝트의 첫 고객이다

우회를 만들지 않는다. 겪은 것은 [업스트림 요구사항 문서](cordboard-upstream-requirements.md)에 모아
이슈로 올린다. 우회 코드를 만들면 두 번 손해다 — 코드가 남고, 스펙은 그 요구를 못 듣는다.

**현재 상태 (2026-09-12, 0.1.0b3 실측)** — 열려 있는 것은 AT-1(depth≥1에서 부모 노드 소실)과
AT-6(LangGraph 지원 범위)이다. AT-2·AT-3은 실험적 확장으로, AT-4는 정의로 답이 왔고, AT-5는 전제가
틀렸다가 해결됐다. ADR-0014·0015 이후 **어느 항목도 연결을 막지 않고** 뷰어와 경고의 품질에만
걸린다. 항목별 실측과 cordboard에서 걸리는 곳은 [업스트림 요구사항 문서](cordboard-upstream-requirements.md)의
상태표를 따른다. RS-1(공개 exporter 통합), RS-2(`block` 호출자 계약), RS-5(릴리스 가용성)는 #5에서 검증됐다.

**실측된 좋은 신호** — `agent-topology` beta.1 → beta.2에서 같은 그래프의 `structureHash`가
동일했다(`d0b436…`). 포맷이 두 릴리스를 건너 안정적이었다는 증거다. beta.2 → beta.3에서도
다른 예제 그래프의 해시가 같았다(`192398ec…`, 2026-09-12).

## 외부 프로젝트 두 개가 실물이 됐다 (2026-09-10)

| | 상태 | cordboard에 미치는 영향 |
|---|---|---|
| [`agent-topology`](https://github.com/agent-topology/agent-topology) | **0.1 public preview.** PyPI 2 + npm 2 패키지, Python·TypeScript 생산자, 정본 JSON Schema | ADR-0009 · 0011 · 0012 갱신 |
| [`redact-secret`](https://github.com/redact-secret/redact-secret) | Rust 코어·바인딩 릴리스. 2026-09-11 Python 0.1.0b1 설치 검증 | ADR-0006 갱신 |

**셋이 결정을 실제로 바꿨다.**

**① R3가 두 번째 타격을 받았다 (0007).** `agent-topology` 0.1은 여러 목적지가 **대안인지 전부 실행되는지 확립하지 않는다.**
R3은 "병렬 분기 안의 인터럽트"를 찾는 규칙이라 코어 문서만으로 구현할 수 없다.
→ **R3은 LangGraph 전용 규칙**이 되고, 거부 조건 1을 두 군데서 못 넘는다. 예외로 유지하되 선례로 삼지 않는다.

**② 커스텀 detector가 불가능하다 (0006).** 모든 detector는 Rust 코어에서 돌고 바인딩은 새 구현을 만들 수 없다.
`redaction.extra_patterns` 계획이 폐기됐다. 반면 **기본 정책이 우리가 쓰려던 표와 같아서** cordboard는 정책을 정의하지 않는다.

**③ LangGraph 버전이 묶인다 (0001).** 생산자가 검증된 좁은 범위만 지원한다.
"그래프마다 자기 의존성"이라는 약속에 구멍이 생겼다 — 파이썬 버전은 달라도 되지만 LangGraph 버전은 공통 범위 안이어야 한다.

그리고 두 프로젝트가 내 프로토타입보다 나은 점 둘을 기록해 둔다.
**픽스처가 언어 중립 `fixture.json` 레시피**라는 것, 그리고 **`gaps`와 `producerLimitations`의 분리** —
내 설계는 항상 존재하는 한계를 gap에 넣어서 모든 문서를 영구히 incomplete로 만들었을 것이다.

## 코드가 문서를 고친 첫 사례

`agent-topology`의 LangGraph 생산자를 실제로 만들어 돌린 결과가 ADR 셋을 고쳤다.
설계만으로는 안 나왔을 것들이다.

| 발견 | 고쳐진 곳 |
|---|---|
| 정적 인터럽트는 `node.metadata`에서 파생되지만 **동적 `interrupt()`는 전혀 안 보인다** | **0007** — R3에 사각지대가 생겼다. 정적만 거부, 동적은 선언에 의존 |
| 조건부 라벨이 `edge.data`에 살아 있다 | 0011 — 뷰어가 분기 이유를 표시할 수 있다 |
| path map 없는 조건부 엣지는 목적지가 빠지는 게 아니라 **가짜 엣지를 만든다** | 0011 — `ORPHANED_NODES` 갭이 탐지 신호 |
| 소스 해시보다 **구조 해시**가 표류 검사에 맞다 | 0011 — 주석·공백 변경으로 오탐이 안 난다 |

0011의 Action Item 1·2·3이 이 과정에서 닫혔다.

## 최소 실행 계약 검증 (2026-09-11, #4)

[최소 그래프](../minimal-graph.md)는 Python 3.12/uv/pytest로 실행된다.
ADR-0004·0008의 예제를 `fast/failed → fast/escalated → deep/passed`로 정정했다.
승격은 정확히 1회이며 같은 Tier 재시도는 승격이 아니다.
`passed`·`repaired`·최종 `failed`, 필수 Subject, 실행별 독립 상태를 검증한다.
이 작업은 고정 응답과 메모리 내 기록만 사용한다. 위 마스킹 선행 조건을 변경하거나
Collector·아카이브 관문을 완료한 것이 아니다.

## 아카이브 구현 정정 (2026-09-11, #5)

- **0006:** 공개 exporter 경계에서 전체 OTLP span envelope를 처리하고 성공 후 스탬프.
  block은 치환 결과가 있어도 전체 span 억제. 별도 정책·커스텀 detector 계획 폐기.
- **0005:** Collector 0.148.0의 append 모드 제약을 반영해 UTC 수신 날짜별 JSONL,
  Collector 종료 후 닫힌 날짜 파일의 외부 gzip 압축으로 구체화했다.
- **0002:** Run 루트에 `cord.semconv.version=0.1.0`을 기록하는 헬퍼가 생겼다.

전체 플랫폼이 구현됐다는 뜻은 아니다. [범위·검증](../archive.md)을 참조한다.


## 아카이브 질의 구현 정정 (2026-09-11, #6)

- **0002:** 명시적 `cord.graph.id` 전파와 Run semconv `0.2.0`. 기존 정체성 없는
  아카이브는 수정·추론 없이 거부하고 재실행한다.
- **0005:** `archive-escalations` 구현. 종료 시각 56일 경계, span_id 중복 제거,
  Graph/Node별 결정적 top-N 및 실제 Collector 캡처의 알려진 정답을 검증했다.
- **0008:** Graph/Node 복합 집계로 예제 정정, 잘못된 Attempt 부모의 오류 검증 완료.

[명령과 증거](../archive-query.md). #4 그래프와 #5 exporter의 직접 연결은 여전히 후속이다.


## LiteLLM 실행 연결 (2026-09-11, #8)

- **0004:** DB 없는 `fast`/`deep` 프록시 및 별도 설정 검사 명령 구현.
- **0006:** 공개 CustomLogger에서 metadata만 계측, 기존 redacting exporter 재사용.
  실제 Collector에서 credential 치환·block 억제와 직접 Attempt 부모를 검증.
- **0008:** 그래프의 생성·검증을 열린 Attempt에 연결. 저장된 승격 1회 및 같은
  별칭의 모델 매핑 교체 시 승격 0회 확인. 원자적 전환 헬퍼는 미구현.

[실행 증거](../model-proxy.md). 실제 프로바이더 smoke는 자격증명이 없어 미실행이다.

## Aegra 실행과 Slice 0 종료 증거 (2026-09-11, #9)

- **0003:** Aegra 0.10.4는 재개 요청에도 새 API Run ID를 발급한다. 독립 실행은
  새 Thread/API Run과 하나의 trace로 구현했고, 논리 Run의 재개 연속성은 후속으로
  명시했다. Subject는 콜론 검사 없이 불투명한 필수 문자열로 기록한다.
- LiteLLM과 Aegra의 Uvicorn 요구사항 충돌 때문에 별도 uv 환경·lockfile을 사용한다.
  공통 runtime을 공유하고 Postgres 서비스는 하나다.
- 실제 Aegra → 그래프 → LiteLLM → Collector 아카이브의 40개 span과 승격 2회,
  상태 격리, 동시 실행 부모 관계, redaction과 fresh-archive 관문을 검증했다.

[전체 재현과 종료 체크리스트](../aegra.md). #8의 실제 프로바이더 증거는 여전히
자격증명이 없어 미실행이며 Slice 0·#7·#9의 전체 완료를 주장하지 않는다.


## 교환원 경계 정정 (2026-09-11, #7)

[ADR-0013](0013-switchboard-boundary.md)이 ADR-0004의 공용 게이트웨이 강제를 대체한다.
모델 구성·키·SDK·Tier 정책은 그래프 소유이며 `cord.yaml`/`x-cord`에는 넣지 않는다.
LiteLLM 코드는 선택적 예제로 이동했고 기본 설치에서 빠졌다. Run semconv 0.3.0은
Tier 없는 Attempt를 허용하며 질의는 기존 0.2.0도 읽는다.
위의 이전 구현 기록에 나온 실제 공급자 미검증은 그대로이나,
이를 Cordboard 공통 완료 조건으로 삼았던 판단은 철회한다.
[현재 검증과 이슈 범위 정정](../switchboard-boundary.md)을 따른다.

## 첫 실제 소비자와의 span 트리 조정 (2026-09-12)

`workbench`(ghpr)는 이 저장소 밖에서 이미 돌고 있는 LangGraph 애플리케이션이고,
자체 SQLite 트레이서를 갖고 있다. cordboard가 관측할 첫 실제 그래프로 검토하면서
두 프로젝트의 span 트리를 직접 비교했다.

**충돌은 없었다.** 그쪽 ADR-006의 "재시도는 형제이지 자식이 아니다"가 금지하는 것은
`attempt 2`를 `attempt 1` **안에** 넣는 모양이고, 우리도 그렇게 하지 않는다. 실제
차이는 Run과 Attempt 사이의 Step 한 겹뿐이었다.

**그 겹이 없으면 어떻게 되는지가 저쪽에서 관측됐다.** `workbench`는 `repaired`를
나중에(ADR-012) 추가했고, Step span이 없어서 Attempt에 얹었다. 결정적 수리가 일어나면
모델은 실제로 틀렸는데 그 Attempt가 `repaired`로 기록돼, 모델 품질 평가에서 틀린
출력과 맞은 출력이 같아진다. ADR-0008이 "목록이 두 가지를 뭉갠다"고 예측한 현상을
독립적으로 만난 사례다. 우리 구조(`Step=repaired`, `Attempt=failed` + 위반 규칙 보존)를
유지한다.

**대신 저쪽에서 규칙 하나를 가져왔다.** 인터럽트에서 Step span을 닫고 재개 때 새 span을
연다 — [ADR-0008의 추가 절](0008-outcome-split.md)에 기록했다. 한 달치 실제 데이터에서만
보이는 결함이라 설계로는 나오지 않았다.

아직 구현이 아니다. `workbench` 연결 자체가 미착수이고, 이 조정은 아카이브가 굳기 전에
트리 모양을 맞춰 둔 것이다.


## 그래프 단위 설정 폐기 (2026-09-12)

[ADR-0014](0014-no-graph-descriptors.md). 초기 설계부터 그래프마다 하나씩 붙는 설명 파일
`cord.yaml`과, 그 내용을 매니페스트에 싣는 `x-cord` 절이 계획돼 있었다. 실물은 한 번도 없었고,
계획 키는 ADR 일곱 곳의 체크되지 않은 Action Item에 흩어져 있었다.

모아 보니 거의 전부 **그래프 하나를 묘사하는** 항목이었다. 이름, 어느 노드가 인터럽트하는지,
얼마나 펼쳐 볼지, 어떻게 띄울지. 교환원이 하는 일이 아니다. 그래프에 대한 사실은 이미 그래프
쪽에 있다 — `compile(name=...)`, `describe(graph_id=..., depth=...)`, Aegra 배포 설정.

그래서 둘 다 없앤다. cordboard는 그래프가 낸 문서를 그대로 읽고, 그래프를 붙일 때 cordboard
쪽에 쓰는 것은 없다. 앞으로 설정이 필요해지면 연결 단위(Deployment 목록, 트리거, Subject 추출,
동시성, 만료)로만 둔다. 판단 기준은 하나다 — **그 값이 그래프를 묘사하는가, 연결을 묘사하는가.**

이 틀이 만든 가장 구체적인 결함은 ADR-0011 §2의 "cordboard가 생성 문서의 이름을 덮어쓴다"였다.
함께 철회했다. 관련 ADR 여덟 곳에 날짜 붙은 정정 절을 두었고 관련 Action Item은 취소선으로 폐기했다.


## 연결을 막지 않는다 (2026-09-12)

[ADR-0015](0015-never-block-connection.md). ADR-0014의 검사를 카탈로그 규칙에 대 보니, 거부 규칙
셋(R1 매니페스트 없음, R2 표류, R3 병렬 분기 안 인터럽트)이 모두 그래프가 자기를 어떻게 설명했는지나
어떻게 짜여 있는지를 보고 연결을 거부하고 있었다.

그런데 연결과 기록은 매니페스트 없이 이미 된다 — #7과 #9의 실행이 그랬다. 매니페스트를 관문으로
두면 생산자의 LangGraph 지원 범위가 곧 연결 조건이 되고, R3은 실험적 필드에 거부를 걸게 된다.

그래서 매니페스트는 뷰어의 선택적 입력이 되고, 카탈로그에는 거부가 없다. R1은 없어지고 R2·R3은
경고다. 표류가 만드는 거짓말은 연결이 아니라 화면에서 막는다 — 표류한 그림은 낡은 상태로 표시하고
실행 기록을 대조하지 않는다. 이 결정으로 업스트림 항목들은 전부 연결 조건에서 뷰어·경고 품질의
문제로 내려갔다.
