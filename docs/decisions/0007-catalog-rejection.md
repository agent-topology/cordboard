# ADR-0007: 카탈로그는 세 경우에만 거부하고, 나머지는 경고한다

**Status:** Accepted — 거부 규칙 R1·R2·R3은 [ADR-0015](0015-never-block-connection.md)가 대체 (경고 목록과 거부 규칙 추가 조건은 유지)
**Date:** 2026-09-10
**Deciders:** 단독 (로컬 도구, 저자 = 운영자)
**관련:** ADR-0002 (Graph의 정체성), ADR-0009 (well-known 두 문서), ADR-0011 (Manifest 파생)
**슬라이스:** 1 — 카탈로그가 생기는 시점

> **범위 확대 기록.** 이 ADR은 원래 "병렬 분기 안의 인터럽트를 거부한다" 하나만 다룰 예정이었다. ADR-0009와 0011을 쓰면서 거부 규칙이 셋으로 늘었고, **거부는 사용자를 막는 유일한 행위**이므로 근거가 흩어져 있으면 안 된다. 세 규칙과 거부하지 않는 것들을 한 문서에서 다룬다.

---

## Context

카탈로그가 하는 일은 등록된 Deployment들의 두 문서(ADR-0009)를 긁어 하나로 답하는 것이다. 그 과정에서 문서가 이상하면 어떻게 할지 정해야 한다.

### 이건 로컬 도구다

혼자 쓰는 도구에서 **막는 것보다 보이는 게 낫다**는 것이 기본 성향이다. 규약을 어겼으면 내가 고치면 되고, 등록을 막으면 그냥 도구를 안 쓰게 된다.

그래서 초기 설계의 정책은 관대했다 — "등록은 막지 않되 경고를 남긴다."

### 그런데 그 정책이 세 곳에서 무너졌다

**하나 — 정체성이 없는 것은 등록할 게 없다.**
ADR-0002에서 Graph를 "Manifest로 자기를 설명하는 실행 단위"로 재정의했다. 레포도 프로세스도 정체성이 아니고 계약이 정체성이다. 그러면 계약의 필수 부분이 없는 것은 "불완전한 Graph"가 아니라 **Graph가 아니다.**

**둘 — 조용한 거짓말은 경고로 못 막는다.**
ADR-0011에서 Manifest 표류를 다뤘다. 표류한 상태에서도 시스템은 정상 동작하고 화면도 뜬다. 경고는 며칠 뒤 눈이 걸러내고, 그때부터 뷰어가 거짓말한다. **어긋난 Manifest는 없는 것보다 나쁘다.**

**셋 — 되돌릴 수 없는 상태로 들어가는 길이 있다.**
병렬 분기 안에 인터럽트가 있으면 동일한 인터럽트 ID가 생성되어 다중 재개가 불가능해진다(LangGraph 미해결 이슈 #6626). 걸리면 그 Run은 **영원히 재개 불가**다. 경고를 읽고도 실행하면 데이터가 아니라 시간을 잃는다.

### 그리고 우리가 막을 수 있는 것과 없는 것이 다르다

플랫폼은 그래프 코드를 안 본다. 그래서 코드 안의 문제는 감지만 하고 막을 수 없다.

| | 볼 수 있나 | 막을 수 있나 |
|---|---|---|
| derived 절이 있는가 | ✓ 문서 | ✓ |
| 코드와 게시본이 같은가 | ✓ 해시 | ✓ |
| 병렬 분기 안에 **정적** 인터럽트가 있는가 | ✓ `edges[].kind` + `nodes[].interrupts` | ✓ |
| 병렬 분기 안에 **동적** 인터럽트가 있는가 | ✗ 노드 본문 | 선언에 의존 |
| 인터럽트 앞에 부작용이 있는가 | ✗ 코드 안 | ✗ 감지만 |
| 상태 이름이 충돌하는가 | ✗ 코드 안 | ✗ |

## Decision

### 거부하는 세 경우

| # | 조건 | 판정 시점 | 이유 |
|---|---|---|---|
| **R1** | `agent-topology.manifest.json`의 `derived` 절이 없다 | 등록 | 정체성이 없다. 등록할 대상이 없다 |
| **R2** | 파생 결과 ≠ 게시본 (표류) | 기동 | 조용한 거짓말. 경고로 못 막는다 |
| **R3** | 병렬 분기 안에 **정적** 인터럽트 노드가 있다 | 등록 | 재개 불가 상태로 가는 길. 비가역 |

> **갱신 2026-09-11 — 앞선 갱신을 철회한다.**
> 2026-09-10에 "R3은 코어 문서로 구현할 수 없고 LangGraph 전용 규칙이 된다"고 적었다. **틀렸다.**
> `agent-topology` README의 *"대안인지 전부 실행되는지 확립하지 않는다"* 를 "구분할 수 없다"로 읽었는데,
> 실제 뜻은 *"`direct` 팬아웃이 반드시 병렬이라고 스펙이 단언하지는 않는다"* 이다.
> **구조적 구분은 코어에 있다.** 0.1.0b1 출력을 실제로 확인했다.
>
> ```
> draft   ['direct', 'direct']           ← 동시 실행
> gate    ['conditional', 'conditional'] ← 갈림길
> ```
>
> R3은 코어 필드 둘만으로 판정된다 — `edges[].kind` 와 `nodes[].interrupts`.
> `x-langgraph`에는 `name`과 `sentinel`뿐이라 확장을 읽을 필요도 없다.
> **R3은 거부 조건 1을 통과한다. 프레임워크 전용 규칙이 아니다.**

**R3에는 사각지대가 있다.** `agent-topology` 생산자를 실제로 만들어 확인한 결과, LangGraph에서
컴파일 시점에 선언된 인터럽트는 `node.metadata['__interrupt']`로 파생되지만
**노드 본문 안의 `interrupt()` 호출은 컴파일된 그래프에서 전혀 보이지 않는다.**

그래서 R3은 두 갈래가 된다.

| 인터럽트 종류 | 보이나 | 처분 |
|---|---|---|
| 정적 (`compile(interrupt_before=[...])`) | ✓ 파생됨 | **R3 — 병렬 분기 안이면 거부** |
| 동적 (노드 안의 `interrupt()`) | ✗ 안 보임 | `declared`에 적으면 R3 적용. 안 적으면 경고 |

`cord.yaml`의 `nodes[].interrupts: true`가 동적 인터럽트를 신고하는 유일한 경로다.
파생된 정적 인터럽트와 대조해서 **선언은 있는데 파생에 없으면** 동적으로 간주하고 R3을 적용한다.
반대로 **파생에는 있는데 선언에 없으면** 경고한다 — 저자가 모르고 있을 수 있다.

### 거부의 조건 — 셋을 다 만족해야 한다

새 거부 규칙을 추가하려면 아래를 전부 통과해야 한다. **이 목록이 이 ADR의 실질적 내용이다.**

1. **문서만 보고 판정할 수 있는가.** 코드를 봐야 하면 감지만 한다
2. **거짓 양성이 사실상 없는가.** 정상적인 그래프가 걸리면 안 된다
3. **통과시켰을 때의 손해가 되돌릴 수 없거나 조용한가.** 시끄럽고 가역이면 경고로 충분하다

R1과 R2는 셋을 다 만족한다.

R1과 R2는 셋을 다 만족한다. **R3도 조건 1을 만족한다** — 코어 필드 둘로 판정된다.

**다만 R3에는 사각지대가 하나 남는다.** 동적 인터럽트(노드 본문의 `interrupt()`)는 어떤 문서로도 안 보인다.
그건 `declared`에 의존한다. 조건 3의 무게(재개 불가는 비가역)를 감안해 사각지대가 있어도 유지한다.

**그리고 이건 R3의 결함이 아니라 정적 분석의 한계다.** 새 거부 규칙을 제안할 때
"R3도 불완전하잖아"를 근거로 쓰지 않는다.

### 경고하는 것 — 목록

거부하지 않지만 카탈로그가 표시한다.

| 조건 | 왜 거부하지 않나 |
|---|---|
| 조건부 엣지의 목적지가 선언되지 않음 | 파생의 한계이지 그래프의 결함이 아니다. 정상적인 코드가 걸린다 |
| `declared` 절이 부분적 (승인·트리거 없음) | 선언한 만큼만 기능을 얻으면 된다. 사람의 판단이므로 미룰 수 있다 |
| Subject 추출식이 잘못됨 | 증상이 즉시 보인다 — 트리거가 안 걸린다 |
| Node 이름 충돌 | 뷰어에서 눈에 띈다. 그리고 우리 문제가 아니라 그 그래프의 문제다 |
| 인터럽트 앞 부작용 (`side_effects_before` 미선언) | 코드를 못 본다. 감지만 가능 (ADR-0006 계열) |
| A2A Agent Card 부재 | 우리 기능에 필요 없다. 외부 노출을 안 하면 그만 |
| Deployment 응답 없음 | 일시적일 수 있다. `unreachable`로 표시하고 Signal은 보류 |

### 거부의 형태 — 사람이 고칠 수 있게

거부는 항상 **무엇이 왜 틀렸고 어떻게 고치는지**를 말한다.

```
✗ issue-resolver — 등록 거부 (R3)
  병렬 분기 안에 인터럽트 노드가 있습니다.
    branch: draft_commit → [review_a, review_b]
    interrupt: review_b
  LangGraph 미해결 이슈로 이 구성은 재개가 불가능해집니다 (#6626).
  → 인터럽트를 병렬 구간 밖 직렬 노드로 옮기세요.
```

**규칙 코드(R1/R2/R3)를 출력에 넣는다.** 이 문서를 찾아올 수 있어야 한다.

### 우회로를 제공한다 — 단, 명시적으로

R3에는 강제 통과 플래그를 둔다.

```yaml
# cord.yaml
unsafe:
  allow_parallel_interrupt: true   # R3 무시. 재개가 불가능해질 수 있음
```

`unsafe` 네임스페이스에 두는 것이 의도적이다. 그리고 이 플래그가 켜진 그래프는 **카탈로그와 뷰어에 상시 표시**된다. 켜고 잊는 것이 불가능하게.

R1과 R2에는 우회로가 없다. 각각 "정체성이 없다"와 "화면이 거짓말한다"라서 무시할 대상이 아니다. R2의 정상 경로는 `cord sync`다.

## Options Considered

### Option A: 아무것도 거부하지 않는다 (초기 정책)

**Pros:** 로컬 도구의 성향에 맞다. 등록이 항상 성공한다. 사용자가 자기 판단으로 진행한다.
**Cons:** 세 경우에서 무너진다. 특히 R2는 경고가 원리적으로 작동하지 않는다 — 정상 동작하는 시스템의 경고는 걸러진다.

### Option B: 엄격하게 검증한다

파생 가능한 모든 이상을 거부.

**Pros:** 등록된 것은 확실히 건강하다.
**Cons:** 거짓 양성이 생긴다. 조건부 엣지 경고는 애노테이션을 안 붙인 정상 그래프에서 나오고, 그걸 거부하면 멀쩡한 그래프가 막힌다. 그리고 혼자 쓰는 도구에서 막히면 도구를 안 쓰게 된다.

### Option C: 거부 없이 "격리 등록"

이상이 있으면 등록하되 실행은 막는다.

**Pros:** 카탈로그에 보이므로 무엇이 문제인지 안다.
**Cons:** 상태가 하나 늘고, "등록됐는데 못 도는 것"이라는 애매한 존재가 생긴다. 그리고 R1의 경우 격리 등록할 정보 자체가 없다.

### Option D: 세 경우만 거부, 조건을 명문화 ← **채택**

**Pros:** 관대한 기본 성향을 유지하면서 세 구멍만 막는다. 거부 조건이 문서화돼 있어 규칙이 늘어나는 것을 막는다.
**Cons:** 판정이 셋 다 다른 시점(등록/기동)에 일어나 구현이 갈린다.

## Trade-off Analysis

### 거부 규칙이 늘어나는 것을 막는 것이 이 ADR의 목적이다

거부 규칙은 하나씩 보면 항상 타당해 보인다. "이것도 문제니까 막자"가 반복되면 **Option B가 되고, 그러면 도구를 안 쓰게 된다.**

그래서 규칙 자체보다 **규칙을 추가하는 조건 셋**이 이 문서의 핵심이다. 다음에 "이것도 거부할까"가 나오면 셋에 대보면 된다.

### 왜 R2만 기동 시점인가

R1과 R3은 문서만 보면 판정된다. R2는 **코드를 다시 파생해 봐야** 알 수 있고, 그건 그래프 프로세스가 뜰 때만 가능하다(ADR-0011 — 파생은 그래프 자신이 한다).

등록 시점에도 검사하고 싶지만 그러려면 카탈로그가 코드를 봐야 하고, 그게 실패 모드 A다. **시점이 갈리는 것은 경계를 지킨 대가**다.

### R3에만 우회로가 있는 이유

셋의 성질이 다르다.

| | 무엇이 없는가 | 우회 가능한가 |
|---|---|---|
| R1 | 정체성 | 없다 — 우회하면 등록할 대상이 없다 |
| R2 | 진실성 | 없다 — `cord sync`가 정상 경로다 |
| R3 | 안전성 | **있다** — 남의 미해결 이슈이고, 고쳐질 수 있고, 특수한 경우 감수할 수 있다 |

R3은 우리 판단이 아니라 **외부 라이브러리의 현재 상태**에 근거한다. 그 상태가 바뀌면 규칙도 바뀌어야 하므로, 사용자가 자기 위험으로 넘어갈 길을 둔다.

### 로컬 도구에서 거부의 실제 비용

혼자 쓰는 도구에서 거부는 **자기 자신을 막는 것**이다. 그래서 거부 메시지가 "무엇이 틀렸다"에서 끝나면 안 되고 "어떻게 고친다"까지 있어야 한다. 6개월 뒤의 자신은 이 규칙을 기억하지 못한다.

규칙 코드를 출력에 넣는 것도 그래서다 — `R3`으로 이 문서를 찾아올 수 있어야 한다.

## Consequences

### 쉬워지는 것

- 등록된 Graph는 정체성이 있고, 화면이 코드와 일치하고, 재개 불가 상태에 빠지지 않는다
- 새 거부 규칙 제안이 조건 셋을 통과해야 하므로 규칙이 함부로 늘지 않는다
- 거부와 경고의 경계가 문서에 있어서 그때그때 판단하지 않는다
- 남이 만든 Deployment에도 같은 규칙이 적용된다

### 어려워지는 것

- **판정 시점이 둘이라 구현이 갈린다.** R1·R3은 카탈로그, R2는 `cord up`
- **R2가 개발 중에 성가시다.** 의도된 것이지만 `cord sync`가 반드시 편해야 한다
- **`unsafe.allow_parallel_interrupt`가 켜진 채 잊힐 수 있다** → 카탈로그·뷰어 상시 표시로 완화하되 완전히 막지는 못한다
- **경고가 쌓이면 무시된다.** 경고 목록이 일곱 개인데, 자주 뜨는 것부터 발생 자체를 줄여야 한다 (예: 템플릿이 `Command[Literal[...]]` 애노테이션을 기본 포함)
- **R3이 LangGraph 이슈에 묶여 있다.** 그쪽이 고쳐지면 이 규칙은 근거를 잃는다

### 다시 볼 조건

- **#6626이 해결되면** → R3을 경고로 강등하거나 제거
- **동적 인터럽트를 정적 분석으로 찾을 방법이 생기면** → R3의 사각지대가 사라진다. `agent-topology` 쪽 과제
- **LangGraph 아닌 Deployment를 등록하게 되면** → 그 프레임워크에서 `direct` 팬아웃이 병렬을 뜻하는지 확인한다. 다르면 스펙 쪽에 의미 명시를 요청한다
- **거부 규칙 추가 요구가 나오면** → 조건 셋에 대본다. 통과 못 하면 경고로
- **경고를 아무도 안 읽는 것이 확인되면** → 그 경고가 발생하는 원인을 템플릿·스캐폴드에서 없앤다. 거부로 승격하지 않는다
- **거짓 양성이 한 번이라도 나오면** → 그 규칙은 조건 2를 못 넘은 것이므로 즉시 경고로 강등

## 정정 — 동적 인터럽트 신고 경로 폐기 (2026-09-12)

[ADR-0014](0014-no-graph-descriptors.md)가 그래프 단위 설정을 폐기하면서, `cord.yaml`의
`nodes[].interrupts: true`로 동적 인터럽트를 신고하던 경로도 사라진다. R3은 **파생된 정보만으로**
판정한다. 코어의 `nodes[].interrupts`(정적 인터럽트)와 엣지 `kind`는 그대로 쓴다.

잃는 것은 크지 않다. 신고하지 않은 `interrupt()` 호출은 원래 보이지 않았으므로, 신고 경로가
보호하던 대상은 이미 신고할 만큼 조심하는 작성자뿐이었다. 사람이 노드 이름을 적는 목록은
ADR-0011이 코드와 어긋난다는 이유로 버린 형태이기도 하다. 병렬 분기 안의 동적 `interrupt()`
위험(langgraph#6626)은 거부할 대상이 아니라 그래프 작성자에게 알릴 내용이며, 사각지대를
화면에 밝히는 Action 4c는 유지한다.

`unsafe.allow_parallel_interrupt` 키도 함께 사라진다. R3이 경고가 되면서 override 자체가
필요 없어졌다 — 아래 정정 참조.


## 정정 — 거부 규칙을 경고로 (2026-09-12)

[ADR-0015](0015-never-block-connection.md)가 이 ADR의 거부 규칙 셋을 대체한다. 카탈로그에 거부는 없다.

| 규칙 | 이전 | 현재 |
|---|---|---|
| R1 — 파생 구조 없음 | 등록 거부 | 없어짐. 매니페스트 부재는 상태이고, 그래프는 그림 없이 연결·기록된다 |
| R2 — 표류 | 기동 거부 | 경고. 뷰어가 그림을 낡은 상태로 표시하고 실행 기록을 대조하지 않는다 |
| R3 — 병렬 분기 안 정적 인터럽트 | 등록 거부 | 경고. 병렬 여부가 확인되지 않으면 "확인할 수 없음"으로 표시한다 |

Context의 세 논거에 대한 답은 ADR-0015에 있다. 요지는 이렇다. 연결의 정체성은 매니페스트가
아니라 연결 자체에서 온다. 표류가 만드는 거짓말은 연결이 아니라 화면에서 막는다. 재개 불가 위험은
그래프 자신의 실행 안에서 생기므로 cordboard는 보여줄 뿐 막지 않는다.

그대로 남는 것: 경고 일곱 개, 그리고 새 거부 규칙을 추가하는 세 조건. ADR-0015는 여기에 한 조건을
더한다 — 그 규칙은 연결을 묘사해야 하고, 그래프가 어떻게 만들어졌는지를 이유로 삼을 수 없다.
