# ADR-0013: Cordboard는 요청한 그래프를 연결하고, 모델 선택은 모른다

**Status:** Accepted
**Date:** 2026-09-11
**Deciders:** 사용자 — 교환원 경계 정정 요청
**관련:** ADR-0002 (어휘와 교환원), ADR-0004 (대체), ADR-0006 (마스킹), ADR-0008 (실행 기록), ADR-0009·0011·0012 (발견 계약)

## Context

교환원은 요청한 상대를 연결하고 통화 기록을 남긴다. 통화 내용을 이해하거나
상대가 어떤 도구로 일을 처리할지 결정하지 않는다. 요청자가 어떤 Graph를 실행할지
알면 된다. Cordboard가 그 Graph의 모델 개수·이름·공급자·키를 알아야 한다면
그래프 내부 구현이 플랫폼의 연결 조건이 된다.

ADR-0004는 관측을 위해 모든 모델 호출을 공용 LiteLLM에 통과시키고, 플랫폼이
별칭·Tier 정책을 검사하도록 정했다. 구현에서는 예제의 `fast`/`deep` 검사와
프록시 기동이 `cord-runtime`에 들어갔고, 모델 없는 Attempt에도 Tier를 요구했다.
관측에 필요한 것은 실행 기록 계약이지 특정 모델 호출 경로가 아니다.

## Decision

### 1. 연결 대상은 Graph다

요청자 또는 요청자가 선언한 Rule이 Graph/Assistant를 지정한다. Cordboard는
주소와 실행 API로 그 요청을 전달하고 실행 정체성·상태·기록을 연결한다.
입출력은 실행 API의 payload로 운반할 수 있지만, 내용을 해석해서 그래프나 모델을
고르거나 프롬프트를 만들지 않는다. 그래프 고유 state와 검증 규칙도 해석하지 않는다.

Manifest와 공개 topology, Run/Step/Attempt의 정체성·부모 관계·시간·Outcome은
연결과 기록의 계약이다. 이 계약을 확인하는 것은 그래프의 사업 로직을 아는 것과 다르다.

### 2. 모델 구성 전체를 Graph가 소유한다

모델을 전혀 쓰지 않거나 하나·여럿을 쓰는 선택, 공급자·SDK·게이트웨이 선택,
모델명·별칭·자격증명·재시도·fallback·Tier 사다리는 그래프 저자/운영자의 책임이다.
Cordboard 등록·기동·실행에 이 목록이나 공급자 키를 요구하지 않는다.
`cord.yaml`과 `x-cord`에는 모델 매핑, `tiers`, 모델별 예산이나 키 발급 정책을 넣지 않는다.

LiteLLM은 선택적인 그래프 의존성이다. 공유 인스턴스를 쓰는 것도 운영자의 선택이다.
Cordboard는 LiteLLM 설정을 생성·검사하거나 모든 그래프의 호출 경로로 강제하지 않는다.
예제 그래프의 설정 검사는 `examples/model_proxy`에 두고 배포 runtime wheel에서 제외한다.
루트 기본 설치에도 LiteLLM을 포함하지 않는다. 이 예제만 `--group proxy`로 설치한다.

### 3. 결과를 기록하는 것과 결정을 소유하는 것을 구분한다

그래프가 명시한 `cord.outcome=escalated`는 계속 집계할 수 있다. 모델명·Tier 이름·
순서에서 승격을 추론하거나 검증하지 않는다. Tier 없이 선언된 승격도 집계한다.
선언이 없으면 관측된 승격은 0이며, 실제로 승격하지 않았다는 증명은 아니다.

`cord.tier`와 `gen_ai.*`는 생산자가 선택해 내보내는 선택적 관측 정보다.
Cordboard가 모델 카탈로그를 갖추거나 이를 연결 조건으로 사용할 근거가 아니다.
모델이나 Tier가 없는 Graph/Step/Attempt도 완전한 실행 기록이다.

### 4. 관측 경계는 유지한다

Cordboard에 기록을 보내는 모든 생산자는 전송 전에 공개 redactor로 처리하고,
Collector는 성공 스탬프를 검사한다. 프롬프트·모델 출력 전문을 기록하지 않는다.
선택적인 SDK/프록시 계측도 이 경로를 따른다. 게이트웨이가 없어도 redaction과
trace 문맥 전달은 필요하다. 검증 범위는 수신된 기록이며, 보이지 않는 내부 호출의
전체 개수나 미전송 기록까지 안다고 주장하지 않는다.

### 5. 기록 버전과 호환성

새 Run은 `cord.semconv.version=0.3.0`을 쓴다. Attempt의 `cord.tier`는 생략 가능하고,
있으면 비어 있지 않은 문자열이다. 그 이름의 의미나 모델 대응은 해석하지 않는다.
`step.attempt(1, outcome=...)`는 Tier 없이 실행을 기록한다. 기존 위치 인자 호출도
지원하며 Outcome 생략 시 실패로 시작한다. 성공은 그래프가 명시한다.

질의는 기존 `0.2.0` 기록을 기존 Tier 필수 조건으로 계속 읽는다. 두 버전을 섞어
읽어도 승격의 집계 의미는 같다. `0.1.0`의 Graph 정체성 부재에 대한 거부는 유지한다.
기존 append-only 파일과 정답 픽스처를 수정하거나 모델 정보를 보충하지 않는다.

## Options Considered

- **공용 게이트웨이를 플랫폼 필수 구성으로 유지:** 이전 결정. 그래프 내부 선택이
  플랫폼 셋업에 새어 나오므로 폐기한다.
- **모델 설정 UI만 숨김:** 내부 필수 의존과 Tier 요구가 남으므로 경계를 고치지 못한다.
- **Graph 실행 계약과 관측 계약만 공통으로 유지:** 채택. 모델 연결은 그래프가 소유한다.

## Trade-off Analysis

공통 모델 관리와 전역 가상 키/예산 기능은 Cordboard 범위에서 빠진다. 그래프마다
모델 연결을 준비할 수 있지만, 플랫폼은 그래프 추가나 모델 교체에 맞춰 바뀌지 않는다.
실행 기록의 완전성은 선택한 계측 범위와 전달 성공에 달려 있다. 공용 게이트웨이를
강제한다고 관측이 자동 완전해진다는 이전 ADR의 논거도 철회한다.

## Consequences

- ADR-0004의 공용 LiteLLM 강제, 고정 별칭, `cord up` 모델 설정 lint,
  `cord.yaml` Tier 정책, 플랫폼 가상 키/모델 예산 계획을 대체한다.
- #8의 LiteLLM 코드와 실제 공급자 smoke는 선택적인 예제 통합으로 유지한다.
  실제 공급자 smoke를 실행하지 않은 사실은 그대로이며 통과로 바꾸지 않는다.
- #7·#9와 Slice 0의 공통 종료 조건에서 공급자 계정/키와 특정 모델 호환성을 분리한다.
  기존 GitHub 체크리스트의 해당 조건은 이 결정에 맞춘 범위 정정 대상이다.
  이 로컬 변경이 GitHub 이슈나 milestone을 자동으로 닫지는 않는다.
- `opaque-graph`는 모델·Tier·프록시 없이 다른 입력 구조를 같은 Aegra 클라이언트로
  실행하는 반례다. 실제 Collector 아카이브에서 부모 관계·새 실행·비밀값 부재를 확인한다.

## 정정 — 같은 경계의 다음 단계 (2026-09-12)

위 결정의 "`cord.yaml`과 `x-cord`에는 모델 매핑을 넣지 않는다"는 이제 더 강한 형태로 대체된다.
[ADR-0014](0014-no-graph-descriptors.md)가 `cord.yaml`과 `x-cord` 자체를 두지 않기로 했다.
이 ADR이 모델에 대해 그은 경계 — cordboard는 그래프가 무엇으로 일하는지 모른다 — 를 그래프 전체로
넓힌 것이다. cordboard는 그래프를 묘사하지 않고, 연결하고 기록한다.
