# ADR-0014: Cordboard는 그래프를 묘사하지 않는다 — `cord.yaml`과 `x-cord`를 두지 않는다

**Status:** Accepted
**Date:** 2026-09-12
**Deciders:** 사용자 — "우리가 하는 건 그래프 하나를 표현하는 게 아니다"
**관련:** ADR-0013 (교환원 경계), ADR-0001·0002·0003·0007·0009·0011·0012 (정정 대상)

## Context

교환원은 회선을 꽂고, 무엇을 무엇에 연결했는지, 무슨 일이 있었는지를 기록한다.
통화 내용도, 통화하는 사람이 어떻게 일하는지도 묘사하지 않는다. ADR-0013이 이 경계를
모델 선택에 대해 확정했고, ARCHITECTURE는 실패 모드 A를 "그래프가 새로 붙을 때마다
고쳐야 하는 두 번째 모놀리스"로 정의한다.

그런데 설계 초기부터 **그래프마다 하나씩 붙는 설명 파일** `cord.yaml`이 계획되어 있었고,
그 내용이 그래프 매니페스트 안의 `x-cord` 절이 되도록 짜여 있었다. 이 파일은 코드·스키마·
실물 어느 형태로도 존재한 적이 없다. 계획된 키는 ADR 일곱 곳에 흩어졌고, 파일 전체를
책임지는 ADR이 없었으며, 관련 Action Item은 하나도 체크되지 않았다.

2026-09-12 점검에서 계획 키를 한데 모으자 **거의 전부가 그래프 하나를 묘사하는 항목**이었다.

| 계획된 키 | 묘사하는 대상 | 출처 |
|---|---|---|
| `name` · `version` · `description` | 그래프의 정체 | ADR-0009 |
| `nodes[].interrupts` | 그래프 내부의 특정 노드 | ADR-0007 |
| `unsafe.allow_parallel_interrupt` | 그래프 내부 구조에 대한 예외 | ADR-0007 |
| `derive: depth` | 그래프를 얼마나 펼쳐 볼지 | ADR-0011 |
| `isolation` | 그래프를 어떻게 띄울지 | ADR-0001 |
| `subject: {type, from}` | 입력에서 Subject를 뽑는 식 | ADR-0003 |
| 승인·동시성·트리거 | 실행을 누가 언제 시작하나 | ARCHITECTURE |

마지막 두 줄만 연결에 관한 것이고, 그마저 그래프에 붙어 있을 이유가 없다. 한 그래프를 여러
Signal이 시작할 수 있으므로 Subject를 뽑는 식은 연결마다 다르다.

원인은 cordboard가 그래프의 일생을 쥐던 초기 설계다. `cord new`로 스캐폴드를 만들고,
`cord up`이 매니페스트를 생성하고, Tier 사다리까지 같은 파일에 있었다. ADR-0013이
모델·Tier 절반을 걷어냈지만 "그래프마다 파일 하나"라는 틀은 남았다.

그 틀이 만든 구체적인 결함이 ADR-0011 §2다. 거기서 "cordboard가 `cord.yaml`의 이름으로
생성 문서를 덮어써야 한다"고 정했다. 파생 문서를 소비자가 고쳐 쓰는 결정이고, 전제도
틀렸다. 이름은 원래 `StateGraph.compile(name=...)`로 그래프가 정할 수 있었고, 문서 안
graph id는 `agent-topology` 0.1.0b3부터 `describe(graph_id=...)`로 정할 수 있다.

## Decision

### 1. 그래프 단위 설정 파일을 두지 않는다

`cord.yaml`은 없다. cordboard에 그래프를 붙일 때 cordboard 쪽에 그 그래프를 위해
작성하는 것은 없다.

### 2. 매니페스트에 cordboard 확장을 두지 않는다

`x-cord`는 없다. cordboard는 그래프가 `agent-topology`로 낸 문서를 **그대로** 읽는다.
절을 추가하지도, 값을 고치지도 않는다. Agent Card에도 cordboard 필드를 넣지 않는다.

### 3. 그래프에 대한 사실은 그래프 쪽에서 온다

| 사실 | 출처 |
|---|---|
| 구조 — 노드, 엣지, 정적 인터럽트 | 그래프 프로세스의 `agent-topology` `describe()` |
| 표시 이름 | `StateGraph.compile(name=...)` |
| 문서 안 graph id | `describe(graph_id=...)` |
| 서브그래프 펼치기 깊이 | `describe(depth=...)` |
| 어느 프로세스가 어느 그래프를 호스팅하나 | Aegra 배포 설정 (`aegra.json`) |
| 모델 · 키 · Tier | 그래프 (ADR-0013) |

### 4. cordboard 설정이 필요해지면 보드 단위다

보드가 알아야 할 것은 연결이다. 어떤 Deployment가 꽂혀 있나, 무엇이 무엇을 시작하나
(Signal → Graph, `run.finished` → Graph), 그 연결에서 Subject를 어떻게 뽑고 동시성을
어떻게 제한하나, 승인이 언제 만료되나. 그래프 수만큼 늘어나는 파일이 아니다.

형태는 그것이 필요한 슬라이스에서 정한다 — Deployment 목록은 #12, 만료는 Slice 2,
규칙은 Slice 3. 지금은 `execute(endpoint, assistant, subject, graph_input)`의 인자로 충분하다.

### 5. 동적 인터럽트를 사람이 신고하는 경로를 두지 않는다

R3은 파생된 정보만으로 판단한다. 신고하지 않은 `interrupt()` 호출은 원래 보이지 않았으므로
신고 경로가 보호하던 대상은 이미 조심하는 작성자뿐이었다. 노드 이름을 손으로 적는 목록은
ADR-0011이 코드와 어긋난다는 이유로 이미 버린 형태이기도 하다.

R3이 거부인지 경고인지, override가 필요한지는 같은 날 [ADR-0015](0015-never-block-connection.md)가
정했다 — R3은 경고이고, 막는 것이 없으므로 override도 없다.

## 앞으로 설정을 추가할 때의 검사

> **이 값은 그래프 하나를 묘사하는가, 연결을 묘사하는가?**

그래프를 묘사하면 cordboard에 두지 않는다. 그래프 하나를 붙이기 위해 cordboard 쪽에
무언가를 써야 한다면 실패 모드 A다.

## Options Considered

### Option A: `cord.yaml`을 유지하고 키만 정리

틀이 그래프 단위로 남는다. 다음 기능이 생길 때 "이 그래프의 X"를 적을 자리가 이미 있으므로
같은 문제가 다시 생긴다.

### Option B: 키를 하나씩 다른 곳으로 옮긴다

2026-09-12 점검의 첫 답이었다. 결론(없앤다)은 같지만, 각 키를 "어디로 옮기나"의 문제로
다뤄서 원인 — cordboard가 그래프를 묘사하려 했다는 것 — 을 짚지 못했다.

### Option C: 그래프 단위 설정 자체를 두지 않는다 ← 채택

원인을 제거한다. 위 검사 하나로 앞으로의 설정 추가를 판단할 수 있다.

## Consequences

### 쉬워지는 것

- 그래프를 붙일 때 cordboard 쪽 작성물이 없다.
- 매니페스트가 업스트림 스키마 그대로라 검증과 합성이 `agent-topology` 공개 API로 끝난다.
  업스트림 ADR 0011("합성할 때 어느 쪽 정체성도 고쳐 쓰지 않는다")과도 맞는다.
- 선언과 코드가 어긋날 원천이 사라진다.

### 어려워지는 것

- **동적 인터럽트는 R3가 보지 못한다.** 원래도 신고된 것만 보았다. 병렬 분기 안의 동적
  `interrupt()`가 재개 불가를 만들 수 있다는 위험(langgraph#6626)은 강제 대상이 아니라
  그래프 작성자에게 알려야 할 내용이다.
- **그래프 프로세스가 떠 있지 않을 때** 카탈로그가 보여줄 수 있는 것은 마지막으로 받은 매니페스트다.
  ADR-0001은 이 부분을 "`cord.yaml`에서 매니페스트를 생성한다"에 기대고 있었다.
- **Agent Card의 이름·설명**은 그래프가 정한다. 카드는 등록 필수가 아니다.
- **매니페스트 안의 `graphs[].id`는 정체성이 아니다.** 업스트림 ADR 0011이 정의한 대로 한 문서
  안에서 `element.graphId`와 `subgraphId`가 가리키는 주소일 뿐이고, 여러 그래프를 한 문서로 합칠
  때만 의미가 있다. cordboard는 문서를 합치지 않으므로 이 값을 실행 기록의 `cord.graph.id`와
  맞출 이유가 없다. 그래프 하나짜리 문서는 `main`으로 충분하다. 이 값은 `structureHash`에
  들어가므로, 바꾸면 표류로 보인다.
